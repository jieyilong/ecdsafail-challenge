# Exact-cleanup evaluation protocol

Date: 2026-09-07. This protocol is recorded before viewing the optimized circuit's full-corpus outcomes.

- Parent: `7664bc2`, frozen replay adapter with Q=1,338 and measured T=1,288,559.92169.
- Change only the QROM unload, its dispatch, and dedicated tests. Keep all non-QROM arithmetic and trusted evaluator sources byte-identical.
- Retain a 16-bit quantum address and the runtime two-coordinate-column ABI.
- Enable `WINDOWED_QROM_UNLOAD=split`. Keep the original replay mode available.
- Primary corpus: the same 100,000 inputs generated by `ecdsafail-windowed-independent-random-100k-v1`.
- Development corpus: `ecdsafail-exact-qrom-development-20260907-v1`, distinct from the primary corpus. Test four-call sequences at w=0..6 and at w=10,12 where the full coordinate pipeline uses K=2 lookup.
- Record exact static gate counts and peak Q from the real emitted circuit, not a count-only QROM model.
- Report mean executed T, counted Clifford operations, Q*T, all failure channels and their union, the empirical pass fraction, and Q*T/pass fraction.
- Compare per-input outcomes against the frozen replay window circuit, mixed ping-pong, and windowed Jump-2.
- Use the common nonidentity domain for paired accuracy comparisons. Report the two identity cases separately.
- Retain the exploratory noninferiority margin 0.0005 in absolute failure probability. Report exact paired sign tests and labeled approximate intervals, without treating a small difference as proof of improved arithmetic accuracy.
- Do not tune arithmetic, routing settings, or nonce after primary outcomes are observed. Report every failure.
- The corpus was already studied, so this is an exploratory paired evaluation, not a newly blinded confirmatory test.
- Exact cleanup means no added approximation under its restoration invariant, not all-input correctness of the inherited arithmetic or full-Shor correctness.

The broader benchmark still omits feed-forward depth and physical implementation costs. Any extra measurement or classical-control work must be identified, rather than counted as a universal hardware speedup.
